# 07 · 原型回合规则与验收用例

> 状态：原型基线；流程与边界用于实现，数值为待试玩的初值，不代表已验证平衡性。范围为 R1，MVP 新命令需补充相同规格。

## 1. 原型内容与目标

- 3–5 座相连城市、2 个势力、8–12 名武将、2–3 条报告型事件，默认 1 个玩家势力。
- 每回合一月；原型最多 24 回合。目标游玩时间 15–30 分钟，以试玩记录为准。
- 胜利：回合末玩家拥有全部城市；失败：玩家无城且无野外军队；到第 24 回合仍未胜利，按目标未完成结局处理。
- 同一回合先检查失败，再检查胜利，再检查时限；玩家拥有全部城市才算胜利，冒烟脚本推进 10 回合不代表通关。
- 原型不做俘虏、死亡、搜索、运输、道具、装备、战术棋盘、可选事件链。MVP 再增加搜索/运输/任命、结盟/赠礼；见 `03-content.md`。

## 2. 状态与资源归属

| 对象 | 原型持有的状态 | 不变量 |
|---|---|---|
| 城市 | 归属、金、粮、人口、农业/商业等级、守军 | 资源与守军非负；金粮仅计入所在城市 |
| 武将 | 势力、所在城市或军队、任务 ID | 同时只有一个位置、最多一个执行中任务 |
| 军队 | 势力、主将、兵力、粮、出发城、目标城、剩余路程 | 出征兵力从守军扣除，禁止重复计入 |
| 任务 | 来源命令、执行者、目标、成本、创建回合、剩余回合、状态 | 状态只能从排队→执行中→完成/失败，或排队→取消 |
| 势力 | 城市/军队 ID、外交条约 | 金粮总量由城市与军队汇总，不再维护第二份可消费余额 |

原型初始金粮、等级、每级收入、兵力维护、征兵单价、开发收益、战斗参数均进入版本化规则参数文件。R0 实际初值、单位、上下限、初始局面与舍入规则见 `11-r0-prototype.md` 和 `content/r0/scenario.json`。

- 守军维护从城市粮扣；军队维护从自带粮扣；原型不自动从城市向军队补粮，运输在 MVP 才加入。缺粮结算见 §4。
- 势力金粮总量只读汇总，不作为第二份可消费余额。

## 3. 指令合同

| 指令 | 前置条件 | 接受时成本/占用 | 完成时效果 |
|---|---|---|---|
| 开发 | 己方城市、空闲在城武将、未达等级上限、金足够 | 扣配置的开发费用，占用武将，耗时 1 回合 | 增加所选农业或商业等级；本回合收入已发，下回合才增收 |
| 征兵 | 己方城市、空闲武将、金粮人口足够 | 按人数扣金粮和人口，占用武将，耗时 1 回合 | 新兵加入守军；不能在接受时立即出征 |
| 出征 | 己方出发城、空闲主将、目标为相邻敌城、无有效停战、守军及粮足够 | 兵力和随军粮从城市转入新军队，占用主将 | 道路耗时至少 1 回合；到达后自动战斗 |
| 停战提议 | 双方仍存在、未在停战、使者为空闲在城武将、同一双方本回合无重复提议 | 扣配置的使节费，占用使者，耗时 1 回合 | 对手按双方可见实力比与关系的固定评分接受/拒绝，原型不投随机骰 |

- `duration=1` 的任务在本回合 Resolution 完成；每个任务每回合只推进一次。任务完成/失败后释放执行者，但玩家本回合下令阶段已结束。
- 资源不足、执行者忙碌、目标非法等指令在接受前拒绝，返回错误码和参数，不扣费、不生成任务、不消耗 RNG。
- 接受后资源立即记账；已占用金粮不能再次消费。UI 展示扣费后的余额、已投入成本与预计剩余时间。
- 原型仅允许取消“本回合创建、尚未进入 Resolution”的排队任务：退回全部预扣资源并释放武将。出征取消时军队未移动，兵粮原样回到出发城，军队删除。
- 任务一旦开始，不支持玩家撤回；执行前再次验证关键条件。目标或来源城市易主、执行者离开/失效则任务失败，已付成本不退，必须显示原因；战败征服导致的资源变化另记入战报。
- 后续运输任务必须区分支付掉的费用与在途货物；不得将本节“成本不退”机械套用成货物凭空消失。
- 任务取消、失败、返航时的资源/部队/主将去向见 §5 的“任务结束与失败处理”。

## 4. 固定结算顺序

1. **TurnStart**：指定回合与日期 → 城市收入 → 城市守军维护（扣城市粮）→ 军队维护（扣自带粮）→ 缺粮惩罚 → 到期条约失效 → 报告型事件。每项都有完成标记，读档不会重算。
2. **PlayerPhase**：玩家下令/取消任务；可以在这里存档；提交结束回合后锁定输入。
3. **AIPhase**：所有 AI 读取同一个阶段起点快照，按稳定顺序提交合法命令。原型使用与玩家相同的公开信息；AI 不读取玩家隐藏的排队命令，不绕过费用和占用规则。
4. **Resolution**：任务推进 → 开发/征兵 → 外交 → 行军到达 → 战斗与占领 → 失败任务清理。MVP 的到期运输插在征兵后、外交前。
5. **TurnEnd**：报告型事件 → 胜负/时限 → 生成报告、保存安全点。未结束则进入下一回合 TurnStart，最终停留在新的 PlayerPhase。

阶段内统一按“任务类别优先级、目标 ID、创建回合、势力 ID、命令序号”排序。所有 ID 比较使用与语言环境无关的序数比较，不能依赖字典迭代或本地化名称顺序。

缺粮的原型规则：守军维护从城市粮扣，军队维护从自带粮扣；余额不足时扣至零，再按配置比例减兵，向下取整但至少损失一兵（有兵时），生成缺粮报告。军队兵力归零则解散，主将转移规则见下一节。原型不自动从城市向军队补粮；运输在 MVP 加入。具体维护系数必须在 G0 参数表中确定。

## 5. 冲突与特殊情况

- 同一武将的第二条指令被拒绝；同一城市允许不同空闲武将各执行一个任务，仍受资源余额和等级上限约束。开发同一等级项目在完成时再检查上限。
- 相向出征的两军沿道路各自前往目的城，原型不做道路遭遇。首版规则需在出征预览明确提示。
- 同城多支攻击军按稳定顺序逐场与当前守方结算，每场重新读取剩余守军和城市归属；若变为己方城市则入驻。多势力围攻公平性待 MVP 试玩复核，不承诺同时战斗。
- 开发与征兵先于战斗结算，新兵可参与本回合守城；出征已扣走的兵不能同时守城。
- 停战提议在 T 回合 Resolution 完成并生效：T/T+1/T+2 有效，T+3 回合 TurnStart 失效。两方同回合相互提议仅处理排序第一条，另一条失败并报告已存在条约。
- 停战生效后，两方已在途的攻击军改为返航，不攻击；按原路返航，距离按道路计算，至少 1 回合，不传送。不支持的目标或军队任务状态必须由 schema 校验拒绝。
- 攻城获胜：攻方剩余兵力入城、军队剩余粮并入城市、主将转为在城；城市剩余金粮归新主人；其他旧主在城武将转移至旧主 ID 最小的城市，无城则离场。败军消灭，主将同样转移或离场；原型不模拟俘虏/追击。缺粮解散也使用此转移规则，携粮为零。
- 回合末事件暂不改变资源或归属；交互事件与额外阶段由 MVP 的专门 ADR 引入，不能在回合结算中偷偷插入玩家输入。

### 任务结束与失败处理

| 情况 | 开发 / 征兵 / 停战 | 出征 | 主将 |
|---|---|---|---|
| 本回合排队中取消 | 全额退回预扣资源，释放武将 | 删除军队，兵粮原样回城 | 空闲，留在原城 |
| 开始后目标/来源城易主 | 任务失败，已付费用不退 | 来源城仍属己方则返航；否则返航至最近己方城；无己方城则解散（兵粮损失） | 非出征：释放，城失守按转移规则；出征：随军返航或解散 |
| 停战生效时在途 | — | 改为返航，不攻击；道路距离至少 1 回合 | 随军返航 |
| 缺粮 | — | 粮扣至零，按配置减兵；兵力归零则解散，兵粮归零 | 解散时转移到旧主 ID 最小的城；无城则离场 |
| 战斗失败 | — | 败军消灭 | 按攻城转移规则 |
| 最大轮数撤军 | — | 攻方剩余军队按撤军返航（见 §6） | 随军返航 |

- “已付费用不退”只指已实际消耗的开发/征兵/外交成本；返航不退还这些成本。
- 返航目标按道路距离、再按城市 ID 排序，保证确定性；不传送。
- 任务失败/取消不消耗 RNG，不产生新的随机状态。
- 非出征任务失败时释放执行者；若所在城市已失守，按攻城转移规则处理。

## 6. 自动战斗最小合同

- 输入双方兵力、主将属性、城防与规则参数；输出伤亡、胜负、剩余兵力和逐轮战报。
- 同一战斗每轮根据轮初状态计算双方伤害，统一应用；整数计算、明确舍入，最小有效伤害为 1。双方同时归零时守方保住城市，守军为 0，攻方按败军处理；0 守军城市在下一次进攻时若无援军/新兵，则不进行战斗、攻方直接入驻，该简化需在战前帮助说明。
- 设置最大轮数，达到上限仍未结束则守方胜利，攻方剩余军队按撤军返航，不按败军消灭；返航规则见 §5，必须在战前帮助与战报中说明该原型简化。
- 不预设完整远程/士气/追击模型；先验证兵力、属性、城防是否提供可理解的选择。R0 具体公式、8 轮上限与参数见 `11-r0-prototype.md` §7。
- UI 预计战力不消耗正式战斗 RNG；原型可以使用确定性公式，若引入随机伤害则记录算法版本与当前状态。

## 7. 必须覆盖的验收用例

| 情景 | 预期 |
|---|---|
| 金不足仍尝试开发 | 拒绝；金、武将和任务列表全部不变 |
| 同一武将先开发再出征 | 第二条拒绝，第一条任务保留 |
| 本回合取消征兵 | 金粮人口完全退回；不生成新兵；武将释放 |
| duration=1 的开发完成 | 本回合等级变化，下回合收入变化；维护每回合仅一次 |
| 同城征兵和被攻击 | 新兵先加入守军，再参与战斗；总兵力没有复制 |
| 停战与在途攻击同回合结算 | 接受停战后军队返航，资源和主将位置一致 |
| 中途存读档与连续游玩 | 同版本、同命令下后续规范化 World 哈希一致 |
| 同种子重复运行 | 含 AI 的命令顺序、战报、最终状态一致 |
| 改变 UI 筛选/多看战力预览 | 不改变规则状态、AI 和 RNG |
| 任意固定种子局面推进至 24 回合 | 无负资源、重复占用、失联任务；必有结局或更早结束 |
| 目标城易主 / 来源城易主 | 出征返航或解散；兵粮、主将位置符合 §5 |
| 守军缺粮 | 城市粮扣至零，守军按配置减员并报告 |
| 军队缺粮 | 自带粮扣至零，军队减员/解散，主将转移 |
| 最大轮数 | 守方胜利，攻方撤军返航，不被消灭 |
| 0 守军城市再次被攻 | 无战斗，攻方入驻 |

G0 前人工走通至少 5 回合和一场战斗；G1 将上述边界用例自动化。先验证这些合同，再增加更多系统。
