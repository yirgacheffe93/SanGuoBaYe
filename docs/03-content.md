# 03 · 内容策略：精神续作与 clean-room

> 历史 R0 文档。ADR-0009 已决定按 main/SGBY 导入内容并后置合规工作；本文 clean-room 约束仅用于理解当时决策，现行内容来源见 `provenance.md` 和 `13-main-m1.md`。

## 1. 定位

新游戏是**精神续作（spiritual successor）**，不是复刻：

- 借鉴的是“回合制三国策略”这一类型惯例和玩法体验；
- 使用的是公共领域的历史素材（三国历史、人物、地名、事件）；
- 表达层（代码、数据、美术、文本、音乐、名称、UI、地图布局）全部原创。

## 2. 可以借鉴 / 必须避免

| 可以借鉴（类型/历史层面） | 必须避免（具体表达层面） |
|---|---|
| 回合制、城池经营、武将养成、外交、战斗等类型惯例 | 原游戏的代码、数据结构、数值表、公式实现 |
| 三国历史人物、年份、地名、战役等公共领域事实 | 原游戏的地图布局、城池坐标、美术、头像、图标 |
| 通用的 UI 模式（列表、详情、地图点击） | 原游戏的 UI 外观、配色、字体组合、Logo、名称 |
| “经营—扩张—决战”的高层节奏 | 原游戏的文本、剧情对白、事件脚本、音乐、音效 |
| 自己的历史研究与原创叙事 | 任何从 `.lib` 提取的数据/图片/字体/文本 |

### 灰色地带

“城池有农业/商业/民心”这类高层概念属于类型惯例，可以用；但**具体字段、数值、公式、界面组织**必须自己设计，不能照抄原版表格或反编译结果。

## 3. 历史素材

可用来源：

- 陈寿《三国志》、范晔《后汉书》、司马光《资治通鉴》等公版史书；
- 《三国演义》（公版）作为文学参考；
- 公开的历史地图、学术著作（注意现代译注/地图的版权）；
- 自己的原创考据与写作。

原则：

- 历史事实可用；**具体叙述、对白、人物小传、事件设计必须原创**。
- 不直接复制现代译本的段落；引用要注明来源并控制篇幅。
- 人物画像、地图、UI 不参考原版游戏的具体表达。

## 4. 内容支柱

1. **历史戏剧**：事件有因果，不是随机弹出。
2. **玩家能动性**：内政/外交/军事选择互相影响。
3. **可读性**：信息分层，新玩家不查 Wiki 也能玩。
4. **重玩性**：不同势力、不同事件链、不同结局。
5. **原创表达**：所有文本、美术、音乐都能追溯到自己的来源记录。

## 5. 原型与 MVP 内容清单

### R1 原型（先验收）

- 3–5 城、2 势力、8–12 武将、2–3 条报告型事件；可以先使用虚构测试局面，不要求还原整个历史剧本。
- 开发、征兵、出征、停战提议；自动战斗和战报；15–30 分钟，最多 24 回合，见 `07-turn-rules.md`。
- 占位地图/头像/图标；没有道具、装备、专用编辑器、战术棋盘和交互事件链。R1 采用 `08-ui-design.md` 的简洁国风方向，写实半身立绘后置（ADR-0007）。
- G0 补齐具体 ID 清单、初始归属/资源、道路耗时、费用/收益表、自动战斗公式；本节数量不替代实际数据。

### R2 MVP（原型试玩通过后扩充）

| 类别 | 数量 | 说明 |
|---|---|---|
| 剧本 | 1 | 190 年讨董，聚焦中原/河北/关中 |
| 城池 | 20 | 每城有地形、连接、基础数值 |
| 势力 | 6 | 曹操、袁绍、刘备、孙坚、董卓、公孙瓒（历史人物，原创演绎） |
| 武将 | 60 | 五维属性、特性、忠诚、年龄 |
| 城市指令 | 5 | 开发、征兵、搜索、运输、任命 |
| 军事指令 | 1 | 出征（原型先用自动结算，不做战术棋盘） |
| 外交指令 | 3 | 结盟、停战、赠礼 |
| 事件 | 10 | 历史事件 + 原创支线 |
| 道具 | 0 | 装备/宝物后置；`item.json` 为后置 schema，不作为 MVP 门禁 |
| 战斗 | 1 种 | 自动结算 + 战报 |
| 地图 | 1 张 | 城池图 + 道路，非原版布局 |

目标体验：2–3 小时通关，至少两种结局。

## 7. 数据结构与生产管线

### 核心数据

```text
character.json    id, name, style_name, faction, birth, death,
                  stats{leadership, war, intellect, politics, charisma},
                  traits[], skills[], portrait, bio_key
city.json         id, name, province, terrain, connections[],
                  base{economy, agriculture, defense, population},
                  buildings[]
scenario.json     id, start_date, factions[], city_owners{}, characters[],
                  events[], victory_conditions
event.json        id, trigger, conditions[], options[], effects[], text_keys
unit.json         id, name, type, attack, defense, mobility, terrain_mods
item.json         id, name, type, bonuses, skill, rarity
```

### 管线

```text
策划表（CSV/表格） -> 导出 JSON -> Schema/引用校验 -> 内容包 -> 运行时
```

- 所有文本用本地化 key，不写死在代码/数据里。
- 构建时校验：必填、类型、范围、悬空 ID、重复 ID、本地化缺失。
- 版本化内容包；mod 以后用同一格式。

### 编辑器

先不写编辑器。等 schema 稳定后，再做：

1. 数据校验 CLI（必须最先有）。
2. 地图/城池编辑器。
3. 事件编辑器。
4. 数值平衡表导入。

## 8. 美术、音频、文本

### 美术

- 方向待定：国风插画 / 写实 / 像素。建议先做 1 张风格样片再定。
- 原型必需：可读地图（城池/道路）、势力徽记与色彩、通用头像、UI 组件和行动图标。界面方向与验收见 `08-ui-design.md`；R1/R2 采用简洁国风方向（ADR-0007）。
- R1/R2 的 60 名武将不要求一人一张独立成品头像；写实半身立绘后置，R2 后按样片与预算评估。自动战斗阶段不制作整套战术单位动画。
- 所有素材原创或购买授权；保留授权文件。

### 音频

- 原创或购买授权；不使用原版音乐/音效。
- MVP 可以先用免费/委托的最小音效集。

### 文本

- 中文先行；英文后补。
- 文风：简洁、克制、有历史感，不模仿原版台词。
- 所有文本进本地化表，key 命名有规范。

## 9. 名称与商标

- 不使用《三国霸业》作为产品名、副标题、Logo 或商店关键词。
- 正式名称需做商标检索（中国/美国/欧盟/Steam）。
- 域名/社媒账号提前占位。
- 工作名：`Project Three Kingdoms` / 代号 `rewrite`。

## 10. Clean-room 记录

在 `docs/provenance.md` 维护不含受限内容的来源记录；授权凭证按授权条件保存，不能公开的凭证另存仓库外：

| 资产/内容 | 来源 | 许可/作者 | 日期 | 备注 |
|---|---|---|---|---|
| 示例：字体 | 自购/开源 | OFL/商用授权 | 2026-xx | 附授权文件 |
| 示例：历史地图参考 | 公版史书/自绘 | 公共领域 | 2026-xx | 仅参考，不描图 |

规则：

- 新仓库不放入 iBaye、`baye-alpha`、`.lib` 的任何文件。
- 不把原版截图/数据表放进新仓库做“参考”。
- 如需对照玩法，只记录**高层行为描述**（例如“回合开始先结算收入”），不抄实现。
- 单人开发很难做到严格法律意义上的 clean-room；因此更要保留来源记录，避免复制具体表达。
