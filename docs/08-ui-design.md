# 08 · UI 设计与同步开发

> 状态：设计建议与原型验收基线。R0-S2 已完成可点击地图、低保真主流程及深色/浅色样片，见 `10-r0-ui-samples.md`；仍不是 R1 可玩 UI。R1/R2 采用简洁国风方向（ADR-0007），外部试玩与高 DPI 验证后续进行。

## 1. 目标与视觉方向

让玩家在同一个主界面回答四个问题：我有什么、哪里有风险、现在能做什么、结束回合后发生了什么。

建议采用“简洁国风战略桌面”：低饱和地形底图、墨色面板、米白正文、克制的朱红强调；城市旗号和路线构成主要视觉信息。古典装饰用于标题、边框和少量纹样，正文/数字优先清晰。避免在密集数据背后铺高对比纸纹。

R1/R2 采用此方向：简洁国风、低饱和、墨色/纸本；原型阶段使用通用头像与字母/文字徽记，不要求完成 60 张人物画。写实半身立绘不作为当前阶段承诺，R2 后按样片与预算评估（ADR-0007）。先以同一主界面制作两份风格样片（深色墨色 / 浅色纸本），比较信息可读性与制作成本，再锁定颜色、字体、边框和图标规范。

旧 iBaye UI 计划已归档到 `godot` 分支 `docs/reference/`，仅作历史参考，不作为本分支实现依据。

## 2. 世界地图主界面

```text
┌────────────────────────────────────────────────────────────┐
│ 势力 / 年月 / 回合   金粮汇总与趋势   目标  外交  菜单        │
├───────────┬──────────────────────────┬─────────────────────┤
│ 城池/军队 │                          │ 选中城市 / 军队      │
│ 搜索筛选  │     可平移缩放的地图     │ 归属、资源、守军     │
│ 城池列表  │     城池、道路、旗号     │ 武将空闲/忙碌        │
│ 威胁/任务 │     行军路线与到达时间   │ 开发 征兵 出征 停战  │
│           │                          │ 指令详情与预计效果   │
├───────────┴──────────────────────────┴─────────────────────┤
│ 待执行任务 / 回合摘要       风险提醒           结束回合      │
└────────────────────────────────────────────────────────────┘
```

- 顶栏金粮是全势力汇总，标明“总量”；城市详情显示真正可支出的当地余额，不能用总量误导玩家下令。
- 左侧列表负责快速定位，可按守军、空闲武将、缺粮风险排序；点击后地图定位并更新右侧详情。
- 中部优先保留地图空间；只有可操作路线和当前选择突出显示，不同时铺满所有标签。
- 右侧是上下文面板：己城显示行动，敌城显示已知情报、出征与停战入口；军队显示位置、剩余路程、补给和任务。
- 停战入口：顶栏“外交”列出当前交战势力，选中后可派空闲使者提议；选中敌城时右侧也提供同一入口。
- 底栏常驻任务数量、最近结果和结束回合按钮；展开可看全部任务。原型不加独立科技、装备等空白入口。
- 1280×720 为最小逻辑视口，1440×900 为参考布局；窄视口左栏折叠，右面板覆盖局部地图，不把文字无限缩小。窗口更小时保持最小窗口尺寸。

## 3. 下令流程

选择城市 → 点击行动 → 选择执行武将/人数/目标 → 查看成本与完成时间 → 确认 → 任务立即进入底栏。

| 状态 | 界面反馈 |
|---|---|
| 未选择参数 | 明确指出需要选武将或目标；确认按钮不可提交 |
| 资源或执行者不足 | 行动入口保留，展示具体原因，如“金不足：需要 100，当前 60” |
| 确认前 | 展示当地余额→扣费后余额、占用武将、预计完成回合、取消规则 |
| 已接受 | 任务卡与地图标记更新；轻量提示，不连续弹确认框 |
| 本回合排队中 | 显示“取消并退回成本”，金额来自应用层 |
| 执行中 | 显示剩余回合、目标和已投入成本，不提供无效取消按钮 |
| 执行失败 | 显示失败原因、成本是否退回、可跳转对象；不只有“失败”两字 |

领域层返回结构化错误、成本和预计结果；UI 负责文案与格式化，不能复制规则公式。预览不得改变正式 RNG。战斗预览用“预计/区间”明确不确定性，只有模型能保证时才显示确定结果。

## 4. 结束回合与回合报告

- 下令阶段结束前检查重要风险：缺粮、存在空闲武将、无任务等；仅缺粮等高影响情况触发确认，普通空闲以可忽略提示呈现。
- 确认后立即禁用重复提交，显示“正在结算”；结算完成前不能继续下令或存档。
- 回合报告优先展示：城市得失、战斗结果、缺粮/任务失败、外交变化，再展示普通收入与开发结果。
- 报告条目可以定位城市或军队；默认折叠流水账，可展开查看完整战报和原因。
- 战报先给胜负、伤亡和城池归属，再给逐轮明细；支持立即关闭和快速继续，不强制播放长动画。
- 自动存档失败必须显示可重试提示，不能报告已保存；读取损坏档时保留当前局面并提供备份入口。

### 存读档（R1）

- 主菜单：继续（最近档）、读档、新游戏；游戏内菜单：存档、读档、设置。
- 3 个手动槽 + 1 个 TurnEnd 自动档；条目显示回合、日期、势力；覆盖需确认。
- 只能在 PlayerPhase 存档；结算中禁用；读档失败保留当前局面并提示备份入口；自动存档失败可重试，不能提示已保存。
- R1 不做缩略图、云存档；跨版本兼容提示在 MVP 再补。

## 5. 组件与表现层边界

优先复用：资源数字（余额/变化）、城市行、武将选择行、任务卡、行动按钮、错误提示、确认面板、报告条目、可排序列表。

- 选中城市、地图镜头、页签、排序、悬停属于 UI；任务与资源属于 World。
- 用同一套 ViewModel 驱动地图、列表和详情；事件提示用于反馈，打开面板时仍查询当前快照，避免漏事件导致界面过期。
- 样例数据只用于线框和视觉样片；R1 可玩 UI 必须连接真实命令/规则，不能把模拟数据画面当可玩验收。
- 地图图标用文字/形状配合颜色区分归属、威胁与状态；重要结果不只靠红绿表示。
- 正文采用可读中文字体，建议参考布局下 16–18 逻辑像素；提供 UI 缩放档位，并在 720p、高 DPI 和长中文文本下复核。
- 鼠标完成全流程；Esc 关闭当前浮层，Enter 只确认明确获得焦点的动作；结束回合快捷键需防误触。键盘焦点与导航在 MVP 完善。

## 6. 与规则同步的交付顺序

| 阶段 | UI 交付 | 验证方式 |
|---|---|---|
| R0 | 地图/详情/下令/报告低保真流程；同屏两份风格样片；字体与数据密度规范 | 用样例局面走一次下令、失败、取消与回合报告；样片不作为功能完成 |
| R1 | 简陋地图、城池详情、开发/征兵/出征/停战、任务队列、战报、存读档 | 首个规则闭环即可操作；至少 3 名外部玩家试玩 |
| R2 | 主菜单/选势力、搜索运输任命、完整外交、事件、新手引导、列表筛选、缩放/焦点 | 至少 5 名外部玩家独立完成 MVP；1280×720 和高 DPI 可用 |
| R3 以后 | 战术战场等新增界面 | 对应系统立项后再做，避免提前设计全部菜单 |

每完成一个行动，同步完成“规则合同、最小界面、成功/失败反馈、冒烟验证”；不要先铺满页面，再集中接规则。

## 7. UI 验收

- 新玩家在 10 分钟内独立找到己城、查看当地余额、执行一次行动并结束回合；记录用时与求助次数。
- 能从界面解释一个行动为什么不可用、何时完成、是否能取消。
- 任务取消或失败后，顶部汇总、详情、武将忙碌状态、任务列表一致。
- 停战入口可从顶栏或敌城打开，使者、费用、生效/失效回合可见。
- 存读档：手动槽、自动档、覆盖确认、坏档提示均可用；结算中无法存档。
- 快速双击结束回合仅推进一次；读档后选中对象失效时安全回到地图概览。
- 720p 与高 DPI 下无关键信息遮挡，面板长文本可滚动，弹窗不超出窗口。
- 外部试玩中的阻塞问题修复并复测后，才扩充内容或精修全套美术。
