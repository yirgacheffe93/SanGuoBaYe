# 31 · Main-M4-A 功能收尾与交互补齐

本阶段修复开发审查发现的战斗收尾问题，补齐实际存档入口、战场提示、战术 AI 和生产规则证据。内容 JSON 与存档 schema 6 保持不变。

## 战斗结算与行动边界

- 胜方全部参战武将都归入目标城，包括已击溃、兵力为零的人物；清理其旧订单引用。败方保留既有俘虏/逃回规则。
- 结算后立即更新太守、势力胜负与结束报告，不再等待下一次月末；胜负重复检查不重复发报告。
- 移入城池据点立即检查胜负。战斗结束后拒绝移动、攻击、技能、待机、回合和撤退，避免在结算界面继续改状态。
- 战斗未结算时禁止战略层月度推进。

## 存档流程

新增 `MainSaveCatalog` 与共享存档面板：

- 五个独立文件槽，显示年份、月份、君主、战略/战场、胜负与保存时间。
- 标题页继续最近有效存档、读取存档及返回当前游戏。
- 战略地图与战场均可打开存读档；覆盖已有槽位需确认。
- 旧 `user://main-m2a-save.json` 作为只读兼容入口列出，不自动覆盖或搬迁。
- 损坏或内容不匹配的存档单独显示原因，不阻塞其他槽位；加载失败保持当前会话。
- 冒烟与截图使用系统临时目录下的独立存档目录，不覆盖玩家存档。

保存仍使用原快照、校验和、内容哈希和临时文件替换机制。没有增加新的世界字段或更改旧存档版本规则。

## 战术 AI 与战场提示

AI 与玩家共用可达格、地形阻力、敌方控制区域、射程和目标合法性检查。一次移动选择最终合法落点，避免原逐格循环重复获得整份移动预算。通过距离场绕开障碍，攻击优先选择有效目标，技能按伤害、补兵和状态价值选择，移动后再次检查技能与攻击。

战场显示武将姓氏、我方/敌方颜色、行动标记、当前目标、兵种和状态；展示“已移动，仍可行动”。增加可达格、普通攻击/技能范围和不可用原因，并保留所选技能，避免刷新后自动跳回第一项。地形显示改用规范化地形类别。

AI 是重写策略，未声称与 main 每次决策、RNG 消耗或整场过程逐项等价。

## 真实技能自然判定

`capture-skill-natural.mjs` 生成 `golden-skill-natural.json`：30 个技能各两组受控属性与固定 seed，加两组高属性字节溢出，共 62 场景。

`showSkill` 不覆盖结果，命中与失败由生产 `FgtJNAction` 自然计算。对照兵力、HP/MP、状态、移动力、经验、天气与粮草，修复：

- 智力与等级形成战斗智谋值时的 U8 绕回，以及随机结果的字节截断。
- 围攻由目标周围友军攻击该目标，经验计给施法者。
- 天变、谍报成功获得 8 点经验；谍报不走普通目标地形/兵种限制。
- 天籁按生产数据施加状态 1；急行按当前 main 的普通技能结果处理，不添加未经证实的移动力 +2。
- 普通技能将状态写成数据指定值，包括零值，而非保留旧状态。

记录 `skillStart` 的判定前 RNG。生产动画/提示会额外消耗随机数，最终 UI RNG 不与纯规则层混称。场景通过受控命令调用，不证明原版技能菜单、全部属性组合或完整战术 AI 等价；战斗在 stage5 受控结束。

## 原生赏赐菜单

`capture-reward-ui.mjs` 通过真实地图、命令、道具、人物菜单注入确认键，捕获 11 个场景。`cityMakeCommand` 仅指定赏赐入口，`willGiveTool` 不覆盖结果。

普通道具、三类兵符、满槽、阈值和成功消耗均有生产证据。实际 main 在装备槽已满时也拒绝使用型兵符；修正原 M2C-C 的相反推断。正常使用仍消耗兵符且不占装备槽，阈值保持 `Force>105` / `IQ>105`，水战兵符没有属性阈值。旧 `golden-m2c-c.json` 的 not-captured 是历史记录，本阶段以新证据补齐。
