## 2. 生产 golden 与公式

`content/main/golden-m2d-a.json` 由 `tools/main-import/capture-m2d-a.mjs` 生成。当前包含 10 个场景，在生产 S3 注入受控人物、城市、订单和 RNG，S4 读取真实执行结果，不是 UI 接受测试。Godot/UI 验收另行覆盖。

```text
离间 gate = (执行者IQ - 目标IQ + 50) & 0xff
成功 = rand%100 <= gate
       && rand%100 >= 目标忠诚
       && rand%100 <= 性格系数
性格系数 = 卤莽50 / 怕死30 / 贪财40 / 大志30 / 忠义5
成功忠诚 = max(0, 忠诚-4)
```

生产离间成功 fixture：执行者 IQ 200、目标 IQ 0、忠诚 3、seed 7，忠诚变 0，最终 RNG `712265938`；失败 seed 1 最终 RNG `1103527590`。

```text
招揽 gate = (执行者IQ - 目标IQ) & 0xff
性格系数 = 卤莽15 / 怕死40 / 贪财30 / 大志20 / 忠义5
成功忠诚 = 40 + rand%20
玩家报告另抽 rand%5
```

招揽成功 seed 7：目标由 6 号势力转入刘备，忠诚 43，目标先于执行者插入发起城，执行者归队后位于其前，最终 RNG `2131988640`。seed 63 的末段余数为 0，忠诚 40，最终 RNG `173759992`。失败报告另抽 `rand%3`。

```text
策反 gate = U32(执行者IQ - 目标IQ + 50)
性格系数 = 卤莽30 / 怕死10 / 贪财20 / 大志60 / 忠义5
```

策反成功后城市和城内在职人员归属 `目标人物ID`，在野人员保持无归属，不加入玩家。成功 seed 7 的最终 RNG `2131988640`；除三段判定和对白外，生产还有一次新君通知随机消耗。失败会经历 U32 绕回后的首关和忠诚判定，再抽对白 `rand%2`，seed 1 最终 RNG `662824084`。

## 3. 原版无效果边界

旧 C 参考中的 `RealienateMake/RealienateDrv` 都是空实现。当前生产的 18 号订单没有可开放行为，因此不创建反间玩法。

19 号劝降在受控生产执行中，即使满足旧 C 的城数、IQ 和性格成功条件，仍不改变归属且不消耗 RNG；另一组城数不足场景同样无效果。当前阶段保留其接受、费用、订单与归队，但报告显示“未产生效果”，不把旧 C 的整势力移交逻辑冒充生产功能。后续若补 UI 接受 golden 发现不同，再以新证据修订。

## 4. UI 与侦察

`MainGameSession.GetCommandTargetPersonIds` 提供只读目标 ID。离间/招揽、策反、劝降、招降分别使用合法人物候选，目标项显示城市与忠诚。移动/输送仍只显示真实可达同势力城市。

侦察使用独立目标集合，接受后立即把金粮、后备兵、农业、商业、民忠和人口写入反馈与月报，不延迟到月末。所有界面继续单快照刷新。
