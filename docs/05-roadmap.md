# 05 · 路线图（质量门禁版）

> 不设发布日期，只设**阶段门禁**。每个阶段必须产出可验证的东西，不通过不进入下一阶段。
> 工作量是单人/小团队的粗略量级，不是承诺。

## R0 · 架构与预制作（4–6 周）

**目标**：在写游戏代码前，把“做什么、怎么组织、怎么验证”定下来。

交付：

- [x] 项目宪章（`01-charter.md`）
- [x] 架构草案（`02-architecture.md`）
- [x] 内容策略（`03-content.md`）
- [x] 技术选型草案与 spike 计划（`04-tech-selection.md`）
- [ ] 技术栈 spike + ADR-0003
- [ ] MVP 内容清单（城池/人物/事件/道具）
- [ ] 数据 schema 草案（角色/城市/剧本/事件）
- [ ] 纸面原型：用表格/脚本模拟 5 个回合
- [ ] 名称/商标初查、来源记录模板
- [ ] 明确“第一版不做什么”

**门禁 G0**：

- 技术栈已选定并记录理由。
- MVP 内容量可在一局 2–3 小时内体验。
- 纸面原型能跑通“经营 → 外交 → 战斗 → 回合推进”。
- 数据 schema 能表达 MVP 全部内容。

## R1 · 骨架与领域核心（6–8 周）

**目标**：无 UI 也能跑一局的核心循环。

交付：

- 工程骨架（目录、构建、测试、CI/本地脚本）。
- `World` / `Faction` / `City` / `Character` / `Army` 领域模型。
- 命令/事件总线、回合流水线。
- 数据加载 + schema/引用校验器。
- 固定种子 RNG + 命令日志。
- 单元测试 + 一个场景测试。
- 最小内容：2 个势力、3 座城、5 个武将、1 条命令。

**门禁 G1**：

- 命令行可以推进 10 个回合，输出状态变化。
- 所有内容通过 schema 校验。
- 测试可在无 Godot 环境运行。
- 没有规则写在 UI 里（此时也还没有正式 UI）。

## R2 · 垂直切片（8–12 周）

**目标**：一个 30–60 分钟可玩的切片，验证“内容 → 规则 → UI”全链路。

交付：

- 1 个剧本、20 城、6 势力、60 武将、10 事件、10 道具。
- 5 个城池指令、3 个外交动作。
- 自动结算战斗 + 战报面板。
- 存/读档、主菜单、设置。
- 现代 UI：世界地图、城池、人物、外交、战报、事件。
- 新手引导（最小）。

**门禁 G2**：

- 从主菜单开始，能完成 10 个回合并达成一个结局。
- 新增一个武将/城市只改数据，不改代码。
- 存读档可靠；固定种子回放一致。
- 鼠标可完成全流程，不依赖方向键。
- 5 名外部玩家能独立完成切片（可后补）。

## R3 · Alpha：系统完整（4–6 个月）

**目标**：功能完整，内容还在填充。

交付：

- 完整内政/人事/外交/军事系统。
- 战术战斗（格子、地形、士气、计谋）。
- 战略/运营/战术 AI。
- 事件系统、剧情链、结局。
- 装备/道具/技能。
- 内容管线 + 编辑器（地图/事件/数据）。
- 性能优化、存档迁移、错误处理。

**门禁 G3**：

- 功能清单全部可玩，没有占位 UI。
- 一场完整战役 5–8 小时。
- AI 不明显犯傻；战斗可自动/手动。
- 崩溃率/坏档率可接受。

## R4 · Beta：内容与打磨（4–6 个月）

**目标**：内容完整、可发行质量。

交付：

- 3 个剧本、40+ 城、150+ 武将、100+ 事件。
- 美术/头像/地图/UI 全套；音频。
- 中英双语、字体/排版/适配。
- 平衡性调整、难度分级、成就（可选）。
- 完整教程、帮助、设置、无障碍基础。
- 外部测试、反馈迭代。

**门禁 G4**：

- 内容冻结；只修 bug/平衡。
- 10 小时以上稳定游玩。
- 目标平台（macOS/Windows）构建可运行。

## R5 · 发行（2–3 个月）

- 打包、签名、公证、安装器。
- 商店页面、截图、预告片、Demo。
- 法律/商标/授权复核。
- 发布后补丁流程。

**门禁 G5**：法务通过 + 构建通过 + 商店素材通过。

## 风险登记

| 风险 | 影响 | 应对 |
|---|---|---|
| 范围蔓延 | 高 | MVP 清单 + G0/G2 门禁；新想法进 backlog |
| 战斗系统过重 | 高 | MVP 先自动结算；战术层单独立项 |
| 内容量（人物/事件/美术） | 高 | 先做内容管线；美术风格样片先行；MVP 小规模 |
| 单人时间/疲劳 | 高 | 阶段化、可暂停；每阶段有可玩产物 |
| 技术栈反复 | 中 | R0 spike + ADR；选定后 6 个月内不换 |
| AI 质量 | 中 | 先规则式 + 评分；可解释日志；难度分级 |
| 数据/内容错误 | 中 | schema/引用校验 + 内容测试 |
| 存档兼容 | 中 | 版本化 + 迁移 + 坏档保护 |
| 法律/商标 | 高 | clean-room 记录；发行前律师审查 |
| 美术成本 | 中 | 先定风格；MVP 用少量高质量；可委托 |

## 节奏建议

- 每周一次可运行构建；每两周一次“可玩检查”。
- 每个阶段结束写复盘：什么做多了、什么做少了、下阶段砍什么。
- 不追求“一次做对”；追求“尽早发现不对”。
