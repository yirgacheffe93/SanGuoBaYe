# 05 · 路线图（质量门禁版）

> 不设发布日期，只设**阶段门禁**。每个阶段必须产出可验证的东西，不通过不进入下一阶段。
> 工作量是单人/小团队的粗略量级，不是承诺。
> R0/R1/R2 分别为预制作、15–30 分钟原型、2–3 小时 MVP。R3 以后为候选扩展，MVP 验收后重估。原有工期合计约 14–21 个月，仅为各段量级相加，不是经过产能验证的排期；兼职开发需要重新估算。

## R0 · 架构与预制作（4–6 周）

**目标**：完成足以实现小原型的规则与工具链验证；不要求提前设计所有 v1 系统。

交付：

- [x] 项目宪章（`01-charter.md`）
- [x] 架构草案（`02-architecture.md`）
- [x] 内容策略（`03-content.md`）
- [x] 技术选型草案与 spike 计划（`04-tech-selection.md`）
- [x] 原型回合合同与验收用例（`07-turn-rules.md`；文档完成，数值/参数仍待 G0）
- [x] UI 布局/反馈/同步开发规格（`08-ui-design.md`）
- [x] 技术栈 spike + 新增最终选型 ADR（ADR-0008；实测见 `09-r0-s1-spike.md`）
- [ ] 原型具体内容清单（3–5 城、2 势力、8–12 武将、2–3 报告事件）
- [ ] 初始资源/归属/道路、费用收益表、战斗公式与参数
- [ ] 数据 schema 草案（角色/城市/剧本/事件）
- [ ] 纸面原型：用表格/脚本模拟 5 个回合
- [x] 来源记录模板（`provenance.md`；实际资产来源仍待补）
- [ ] 名称/商标初查
- [x] 明确原型不做道具、装备、编辑器、战术棋盘和交互事件链
- [x] 主界面低保真流程、深色/浅色两份风格样片（`10-r0-ui-samples.md`；外部试玩与高 DPI 后续验证）

**门禁 G0**：

- 技术栈已选定并记录理由。
- 原型输入数据与实际参数可用，资源、行动限制和胜负/时限明确。
- 纸面原型走通至少 5 回合，包含经营、停战、战斗、取消与失败；结算无二次扣费或重复占用。
- 数据 schema 能表达原型全部内容；MVP 扩展字段有清单，允许后续演进。
- UI 线框走通下令、不可用原因、取消、回合报告；样片可读，未要求全套美术定稿。

## R1 · 首个可玩原型（原量级 6–8 周，spike 后重估）

**目标**：规则可独立测试，玩家能通过简陋 UI 完成 15–30 分钟的一局。首个规则闭环即可试玩，不等全部系统就绪。

交付：

- 工程骨架（目录、构建、测试、CI/本地脚本）。
- `World` / `Faction` / `City` / `Character` / `Army` 领域模型。
- 命令处理、通知事件、回合流水线；不做完整事件溯源。
- 数据加载 + schema/引用校验器。
- 固定算法版本 RNG、当前状态存档、命令日志、规范化状态哈希。
- 最小内容：3–5 城、2 势力、8–12 武将、2–3 条报告型事件。
- 开发、征兵、出征、停战、规则式 AI、自动战斗、胜负与时限。
- 简陋地图、详情/下令、任务列表、回合报告、存读档；见 `08-ui-design.md`。
- 规则测试、边界场景、连续游玩与读档一致性验证。

**门禁 G1**：

- 命令行可运行到结局；UI 可完成开发→征兵→出征→AI 应对→胜负→读档继续。10 回合为冒烟检查，另需完整胜负用例。
- 所有内容通过 schema 校验。
- 默认 C# 方案的规则测试在无 Godot 环境运行；改选 GDScript 必须以 ADR 修订为 Godot headless。
- `07-turn-rules.md` 的关键用例通过；同版本回放一致，读档不重算收入/维护，资源非负、武将无重复占用。
- UI 连接真实规则，鼠标可完成全流程，没有规则写进 UI。
- 至少 3 名外部玩家试玩；记录操作阻塞和选择是否可理解，阻塞问题修复并复测后进入 R2。未招到玩家则此门禁保持未通过。

## R2 · MVP（原量级 8–12 周，G1 后重估）

**目标**：原型通过试玩后扩为 2–3 小时、可通关的最小完整版本；保留至少胜利/失败两种结局。

交付：

- 1 个剧本、20 城、6 势力、60 武将、10 事件；道具/装备后置，头像不要求全部独立成品。
- 城市指令 5 个（开发/征兵/搜索/运输/任命）、军事指令 1 个（出征）、外交指令 3 个（结盟/停战/赠礼）；补齐搜索/运输/任命的成本、占用和失败规则。
- 交互事件的选择阶段/存档安全点需先以 ADR 明确，再进入内容生产。
- 自动结算战斗 + 战报面板。
- 存/读档、主菜单、设置。
- 现代 UI：世界地图、城池、人物、外交、战报、事件。
- 新手引导（最小）。

**门禁 G2**：

- 从主菜单开始，能选势力并完成一局、达成胜利或失败；10 回合冒烟检查单独执行。试玩记录实际时长，确认目标为 2–3 小时。
- 新增一个武将/城市只改数据，不改代码。
- 存读档可靠；固定种子回放一致。
- 鼠标可完成全流程，不依赖方向键。
- 至少 5 名外部玩家独立完成 MVP（不得后补）；记录首次行动用时、求助、卡住点、结局与总时长，阻塞问题修复并复测。
- 1280×720 与高 DPI 下关键操作可见、中文不遮挡；不可用/忙碌/排队/失败等反馈齐全。

## R3 · Alpha：候选系统扩展（原量级 4–6 个月，G2 后重估）

**目标**：按 G2 结果选择扩展系统；战术战斗单独立项与原型验证，不自动视为 4–6 个月可完成。下列为候选清单，立项后冻结实际交付与验收。

交付：

- 完整内政/人事/外交/军事系统。
- 战术战斗（格子、地形、士气、计谋）。
- 战略/运营/战术 AI。
- 事件系统、剧情链、结局。
- 装备/道具/技能。
- 内容管线 + 编辑器（地图/事件/数据）。
- 性能优化、存档迁移、错误处理。

**门禁 G3**：

- 功能清单全部可玩，没有占位 UI。
- 一场完整战役 5–8 小时。
- AI 在固定场景不执行非法命令、不反复无收益调兵、可维持补给；冻结对应基准用例。战斗可自动/手动（若该系统已立项）。
- 固定种子长局与存读档回归全部通过，阻塞级崩溃/坏档为零；具体测试种子数与时长在立项时冻结。

## R4 · Beta：内容与打磨（原量级 4–6 个月，扩展范围冻结后重估）

**目标**：内容完整、可发行质量。

交付：

- 3 个剧本、40+ 城、150+ 武将、100+ 事件。
- 美术/头像/地图/UI 全套；音频。
- 中英双语、字体/排版/适配。
- 平衡性调整、难度分级、成就（可选）。
- 完整教程、帮助、设置、无障碍基础。
- 外部测试、反馈迭代。

**门禁 G4**：

- 内容冻结；只修 bug/平衡。
- 10 小时以上稳定游玩。
- 目标平台（macOS/Windows）构建可运行。

## R5 · 发行（原量级 2–3 个月，目标平台与发行范围冻结后重估）

- 打包、签名、公证、安装器。
- 商店页面、截图、预告片、Demo。
- 法律/商标/授权复核。
- 发布后补丁流程。

**门禁 G5**：法务通过 + 构建通过 + 商店素材通过。

## 风险登记

| 风险 | 影响 | 应对 |
|---|---|---|
| 范围蔓延 | 高 | MVP 清单 + G0/G2 门禁；新想法进 backlog |
| 战斗系统过重 | 高 | MVP 先自动结算；战术层单独立项 |
| 内容量（人物/事件/美术） | 高 | 先做内容管线；美术风格样片先行；MVP 小规模 |
| 单人时间/疲劳 | 高 | 阶段化、可暂停；每阶段有可玩产物 |
| 技术栈反复 | 中 | R0 spike + ADR；选定后 6 个月内不换 |
| AI 质量 | 中 | 先规则式 + 评分；可解释日志；难度分级 |
| 数据/内容错误 | 中 | schema/引用校验 + 内容测试 |
| 存档兼容 | 中 | 版本化 + 迁移 + 坏档保护 |
| 法律/商标 | 高 | clean-room 记录；发行前律师审查 |
| 美术成本 | 中 | 先定风格；MVP 用少量高质量；可委托 |
| UI 晚接规则导致返工 | 高 | R1 即有简陋 UI；每个行动同步交付反馈与验收 |
| 确定性/读档漂移 | 高 | 算法与内容版本、RNG 状态、稳定排序、安全点、连续性测试 |

## 节奏建议

- R0 每周交付可复核的规则示例/线框/spike；R1 起每周一次可运行构建，每两周一次可玩检查。
- 每个阶段结束写复盘：什么做多了、什么做少了、下阶段砍什么。
- 不追求“一次做对”；追求“尽早发现不对”。
