# 01 · 项目宪章

> 历史 R0 文档。当前已按 ADR-0009 改为以 main/SGBY 为内容与功能基准；本文的原创数据、clean-room 和小原型范围不再作为当前约束，现行路线见 `05-roadmap.md`。

## 1. 一句话

做一款**现代、可维护、原创**的单机回合制三国策略游戏：保留经典“城池经营 + 武将养成 + 外交 + 战斗”的体验，但用全新的代码、数据、美术和文本实现。

## 2. 产品支柱

1. **历史感**：以《三国志》等正史和《三国演义》的公共领域素材为基础，做自己的历史叙事。
2. **策略深度**：内政、人事、外交、军事互相牵制，不做单纯数值堆叠。
3. **可读性**：现代 UI、清晰的信息层级、鼠标操作优先，不要求背键位。
4. **重玩价值**：不同势力、不同选择、不同事件链。
5. **可维护**：数据驱动、规则与 UI 分离、可测试、可扩展。

## 3. 目标与非目标

### 首个可玩原型（R1）

先验证 15–30 分钟核心循环：3–5 城、2 势力、8–12 武将、2–3 条事件；开发、征兵、出征、停战；自动战斗、简陋地图和城池面板、回合报告、存读档。使用占位头像和通用图标，不做道具、装备、编辑器或战术棋盘。

R1 允许只开放一个玩家势力；对手由 AI 控制。数值与胜负规则见 `07-turn-rules.md`，界面/美术方向见 `08-ui-design.md` 与 ADR-0007（写实立绘后置）。

### MVP 目标（R2）

原型通过试玩后，再扩为一个 2–3 小时可通关的最小完整版本：

- 1 个剧本（例如 190 年讨董）
- 1 张地图，约 20 座城池
- 6 个可选势力
- 约 60 名武将
- 城池经营（开发、征兵、搜将、运输、任命）
- 简单外交（结盟、停战、送礼）
- 战斗：先做**自动结算 + 战报**，不做完整战术棋盘
- 事件：约 10 条原创事件
- 存读档、设置、主菜单
- macOS 可运行

### v1 候选目标（MVP 验收后重估）

以下是扩展方向，不是已经排定的交付承诺；战术战斗单独评估工作量。

- 3 个剧本，40+ 城池，150+ 武将，100+ 事件
- 完整战术战斗（格子战场、兵种、地形、士气、计谋）
- 更完整的外交、人事、装备、科技/政策
- 10–15 小时单局体验
- 中英双语，键鼠完整支持

### 非目标（v1 前不做）

- 多人联机
- 3D、VR、移动端
- Steam 创意工坊 / 脚本 mod（数据 mod 可以后置）
- 全语音、过场动画电影化
- 联机排行榜、成就系统（发行阶段再评估）
- 复用任何原版代码、数据、美术、文本、音乐、名称

## 4. 设计原则

1. **Clean-room**：新工程不包含 iBaye、`baye-alpha` 或原版 `.lib` 的任何代码/数据/素材。具体规则见 `03-content.md`。
2. **Domain-first**：规则、状态、AI 不依赖 UI 或引擎；可以无头运行、批量模拟、写测试。
3. **Data-driven**：剧本、城池、人物、事件、兵种、道具尽量放在数据文件里，代码只实现规则。
4. **Deterministic**：同一规则/内容版本、初始状态、随机算法版本与种子、命令序列下结果一致；存读档恢复 RNG 当前状态，首版不承诺跨版本回放。
5. **UI-independent**：界面只负责展示和收集输入，不实现规则；任何界面都可以替换。
6. **Testable**：核心规则有单元测试；每个阶段有可重复的验收脚本。
7. **Incremental**：每个里程碑都产出可玩/可验证的东西，不做一次性大爆炸。
8. **No premature scale**：先做单剧本、单地图、单战斗模式，再扩展。

## 5. MVP 的“完成”定义

- 从主菜单开始，选势力，进入地图，完成至少 10 个回合。
- 能建设城池、招募/任命武将、发起一次外交、打一场自动结算的战斗。
- 能存档、退出、读档继续。
- 所有内容来自数据文件；新增一个武将/城市不需要改代码。
- 核心规则有自动化测试；同版本固定种子回放稳定，存读档后的后续结果与连续游玩一致。
- 达成剧本胜利或失败条件；完成 10 回合仅是冒烟检查，不能替代通关验收。
- 在 macOS 上以独立窗口运行，无崩溃。

## 6. 成功标准

### 技术

- 规则层可以脱离 UI 运行（headless）。
- 数据校验器能拦住缺字段、悬空 ID、非法数值。
- 一回合结算（含 AI）在普通笔记本上 < 200ms。
- 存档带版本号，可迁移；坏档有明确报错。

### 产品

- 新玩家 10 分钟内理解核心循环。
- 一局 MVP 2–3 小时，有明确的胜负和结局。
- 不依赖原版知识也能玩；老玩家能感到“熟悉的味道”，但内容是新的。

### 过程

- 每个阶段有文档、有验收、有回退点。
- 不出现“为了赶进度把规则写进 UI”的捷径。

## 7. 开发方式

- 设计文档 + ADR（架构决策记录）先行。
- 每个系统先明确规则和输入输出，再同步实现最小 UI；R1 即提供可操作构建。
- 垂直切片优先于横向铺量。
- 每个阶段结束做一次“可玩性检查”，不通过就不进入下一阶段。
- 技术栈未定之前，允许有限的引擎 spike 和 UI 线框验证；正式工程在选型后开始。
